Guida Operativa: Integrazione CI/CD

Progetto: Castello dell'anima (TEI + IA) | File: tei/taxonomy/tassonomia-gh.xml

1️⃣ Verifica la struttura dei file

Il workflow richiede che il repository rispetti questa struttura. Assicurati che i seguenti file siano presenti:

  • ✔ tei/taxonomy/tassonomia-gh.xml
  • ✔ tei/taxonomy/schema/taxonomy-rng.rng (RelaxNG - richiesto)
  • ✔ tei/taxonomy/schema/taxonomy-sch.sch (Schematron - richiesto)
⚠️ Attenzione al queryBinding dello Schematron taxonomy-sch.sch deve dichiarare queryBinding="xslt", non "xslt2". Il motore di validazione usato dal workflow (lxml, in Python) supporta solo Schematron XSLT 1.0. Le regole del progetto non richiedono funzioni XPath 2.0, quindi il cambio è sicuro.

2️⃣ Posizione del Workflow

Il file di configurazione GitHub Actions deve stare esclusivamente qui, alla radice del repository:

Percorso
.github/workflows/main.yml

GitHub Actions non legge configurazioni da nessun altro percorso (es. tei/taxonomy/workflows/ non viene mai eseguito automaticamente).

3️⃣ Cosa verifica lo script?

Il workflow protegge le 8 tassonomie core del progetto:

func risk impact mystic_state operation exposition phase relation

Se uno di questi xml:id risulta assente in tassonomia-gh.xml, oppure il file non è ben formato, non rispetta il RelaxNG, o viola una delle 5 regole Schematron (category-catdesc-present, category-catdesc-not-empty, category-prefix-consistency, taxonomy-category-xmlid-unique, func-branch-consistency), la pipeline interrompe l'esecuzione (status ❌).

Oltre alla fonte, il workflow controlla anche i file in tei/taxonomy/esempio/*.xml:

  • ✔ Riferimenti @ana: ogni token @ana deve puntare a un xml:id realmente dichiarato in tassonomia-gh.xml (nessuna categoria inventata).
  • ✔ Validazione strutturale di ogni esempio contro schema/tei_all.rng.
  • ✔ Guardia di co-occorrenza (cooccurrence_guard.py) sulla combinazione multiassiale dei @ana.

4️⃣ Esecuzione

Il workflow si attiva automaticamente su push o pull request che toccano tei/taxonomy/**, oppure manualmente:

GitHub
Actions → Validate Taxonomy → Run workflow

Monitora l'avanzamento dalla tab Actions del repository.

5️⃣ Test in Locale (Opzionale)

Per validare localmente il file prima del push (richiede xmllint):

Locale
